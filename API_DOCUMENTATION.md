# NIRIKSHAN AI – API Documentation

> Status: **PLANNED**. No endpoint is implemented yet. This is the contract
> the backend and frontend will both follow. All example values below are
> ILLUSTRATIVE PLACEHOLDERS using synthetic IDs, not real data.

## 1. Conventions

- Base URL (local): `http://localhost:8000/api/v1`
- Format: JSON in, JSON out
- FastAPI auto-generates interactive docs at `http://localhost:8000/docs`
- Dates: ISO 8601 strings
- Every response involving data includes `data_origin` (`real` or `synthetic`)
- Errors use this shape:

```json
{ "detail": "Human-readable error message" }
```

| HTTP code | Meaning |
|-----------|---------|
| 200 | Success |
| 201 | Created |
| 400 | Bad input |
| 404 | Not found |
| 422 | Validation error (automatic from FastAPI) |
| 500 | Server error |

## 2. Endpoints

### 2.1 System

#### `GET /health`
Checks that the server is running.

```json
{ "status": "ok", "version": "0.1.0" }
```

### 2.2 Datasets

#### `GET /datasets`
Lists all loaded datasets.

```json
[
  {
    "id": 1,
    "name": "Synthetic demo set",
    "data_origin": "synthetic",
    "row_count": 300,
    "ingested_at": "2026-11-08T10:00:00"
  }
]
```

#### `POST /datasets/synthetic`
Generates and loads synthetic demonstration data.

Request:
```json
{ "n_rows": 300, "seed": 42, "anomaly_fraction": 0.05 }
```
Response (201):
```json
{ "dataset_id": 1, "data_origin": "synthetic", "row_count": 300 }
```

#### `POST /datasets/ingest`
Loads a real file already placed in `data/raw/`.

Request:
```json
{
  "filename": "<file in data/raw>",
  "name": "<descriptive name>",
  "source_note": "<official URL and download date>",
  "period_covered": "<period>"
}
```
Response (201): same shape as above with `"data_origin": "real"`.
Returns 400 if required internal fields cannot be mapped.

#### `GET /datasets/{dataset_id}/quality`
Returns the data-quality report.

```json
{
  "dataset_id": 1,
  "rows": 300,
  "missing_by_column": { "<column>": 0 },
  "duplicates_removed": 0,
  "cleaning_log": ["<description of each change>"]
}
```

### 2.3 Analysis runs

#### `POST /analysis/runs`
Starts an analysis on a dataset.

Request:
```json
{
  "dataset_id": 1,
  "contamination": 0.05,
  "pca_components": 2,
  "lof_neighbors": 20,
  "random_seed": 42
}
```
Response (201):
```json
{ "run_id": 7, "status": "pending" }
```

#### `GET /analysis/runs`
Lists runs with status and parameters.

#### `GET /analysis/runs/{run_id}`
Returns run metadata.

```json
{
  "id": 7,
  "dataset_id": 1,
  "status": "done",
  "data_origin": "synthetic",
  "params": { "contamination": 0.05, "random_seed": 42 },
  "finished_at": "2026-11-08T10:01:00"
}
```

#### `GET /analysis/runs/{run_id}/results`
Paginated scored records.

Query parameters: `flagged_only` (bool), `sort` (`combined_score`), `limit`,
`offset`.

```json
{
  "run_id": 7,
  "data_origin": "synthetic",
  "total": 300,
  "items": [
    {
      "record_id": 12,
      "entity_id": "SYN-MP-012",
      "period": "SYN-PERIOD-1",
      "iforest_score": 0.91,
      "lof_score": 0.84,
      "combined_score": 0.875,
      "is_flagged": true,
      "explanation": [
        { "feature": "utilisation_ratio", "value": 0.12, "peer_median": 0.80 }
      ]
    }
  ]
}
```

#### `GET /analysis/runs/{run_id}/summary`
Counts for dashboard cards.

```json
{
  "run_id": 7,
  "data_origin": "synthetic",
  "total_records": 300,
  "flagged_records": 15,
  "score_histogram": [{ "bin_start": 0.0, "bin_end": 0.1, "count": 40 }]
}
```

#### `GET /analysis/runs/{run_id}/pca`
2-D points for the scatter plot.

```json
{
  "explained_variance_ratio": [0.45, 0.22],
  "points": [{ "record_id": 12, "x": 1.2, "y": -0.4, "is_flagged": true }]
}
```

#### `GET /records/{record_id}?run_id=7`
Full detail for one record, including cleaned values and explanation.

# Anomaly API Response Contract

## 1. Purpose

This document defines the response structure through which the NIRIKSHAN AI frontend will receive anomaly review candidates from the FastAPI backend.

The API will expose analytical review signals generated by the ML pipeline.

## 2. Proposed Endpoint

**Endpoint:** `GET /api/v1/anomalies`

**Purpose:** Retrieve records selected for analytical review.

**Response format:** JSON

## 3. Response Structure

The endpoint will return the following structure:

```json
{
  "status": "success",
  "total_records": 3487,
  "data": [
    {
      "sr_no": 125,
      "work": "Example sanctioned work",
      "state": "Punjab",
      "constituency": "Example Constituency",
      "work_category": "Normal/Others",
      "work_description": "Example work description",
      "recommended_date": "08-Jul-2024",
      "sanction_date": "15-Oct-2024",
      "sanction_amount": 500000,
      "sanction_delay_days": 98,
      "work_status": "Physical Inspection",

      "isolation_forest_score": 0.72,
      "anomaly_percentile": 99.8,

      "state_peer_percentile": 97.5,
      "state_peer_group_size": 125,

      "category_peer_percentile": 96.8,
      "category_peer_group_size": 250,

      "review_signals": [
        "Global Isolation Forest",
        "State-Year Delay Comparison"
      ],

      "review_explanation": "Example analytical explanation.",

      "interpretation_notice": "This is an analytical review signal, not evidence of financial irregularity or wrongdoing."
    }
  ]
}
```

The values above are illustrative and do not represent an actual record.

## 4. Field Definitions

| API Field | Data Type | Description |
|---|---|---|
| sr_no | Integer | Source record number |
| work | String | Work reference |
| state | String | State |
| constituency | String | Parliamentary constituency |
| work_category | String | Work category |
| work_description | String or null | Description of the work |
| recommended_date | String | Recommended date |
| sanction_date | String | Sanction date |
| sanction_amount | Number | Sanction amount in rupees |
| sanction_delay_days | Integer | Days between recommendation and sanction |
| work_status | String | Recorded work status |
| isolation_forest_score | Number or null | Isolation Forest anomaly score |
| anomaly_percentile | Number or null | Global anomaly score percentile |
| state_peer_percentile | Number or null | State-Year delay percentile |
| state_peer_group_size | Integer or null | Eligible State-Year comparison group size |
| category_peer_percentile | Number or null | Category-Year delay percentile |
| category_peer_group_size | Integer or null | Eligible Category-Year comparison group size |
| review_signals | Array of strings | Review methods triggered |
| review_explanation | String | Human-readable explanation |
| interpretation_notice | String | Analytical limitation notice |

## 5. Important API Rules

1. Review signals must be returned as a JSON array, not a Python list encoded as a string.
2. Missing peer-group values must be represented as JSON `null`.
3. Amounts must remain numeric and expressed in Indian rupees.
4. Dates must use a consistent format.
5. The API must not describe candidates as fraudulent or corrupt.
6. Percentiles must not be presented as probabilities.
7. Multiple review signals must remain independently identifiable.
8. The API must not modify the original raw dataset.
